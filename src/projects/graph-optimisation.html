Runtime Scope

The public repo contains the player implementation and whitepaper. It was built within an assignment-provided runtime/harness, so the public repo should not be presented as a standalone complete application.

Problem

An autonomous agent must explore an initially unknown graph, remember routes, handle resources and locks, collect objectives and reach an exit.

What I Built

I built the C# routing logic for graph discovery, BFS, lock-aware routing, Dijkstra, resource handling, treasure/objective planning, area decomposition, MST-style planning, a custom heap, custom hash table and action/path buffers.

Graph Representation

The engine stores graph data in flat arrays instead of an object-heavy graph representation. That makes repeated graph operations easier to reason about under memory and runtime constraints.

Algorithms

BFS handles reachability and traversal planning, while Dijkstra supports weighted path selection. Custom heap and hash storage reduce dependency on higher-level collection abstractions.

Key Technical Decisions

  • Contiguous arrays for graph and traversal state.
  • Open-addressed hash storage for node lookup.
  • Custom binary heap for priority-queue behaviour.
  • Search stamps to avoid clearing arrays between repeated searches.
  • Area decomposition for resource and collection planning.

Evidence

The repository contains an approximately 57KB C# implementation and a 7-page technical whitepaper. The documented complexity is BFS O(|V| + |E|), Dijkstra O((|V| + |E|) log |V|) and expected amortised O(1) hash lookup. I am not claiming runtime benchmarks.

What I Learned

Algorithm design changes when memory layout matters, topology is discovered incrementally, searches repeat and resources change which paths are valid.
