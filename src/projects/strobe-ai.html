Strobe AI

Cloud-native multimodal AI assistant for a social media backend, built around ACP streaming, MCP tools, Amazon Bedrock, user-scoped retrieval and asynchronous AWS processing.

Problem

Photo-sharing systems can store useful personal context, but normal search and feed interfaces do not make that context easy to query. The challenge was to give an assistant access to useful backend capabilities without letting the model control identity, ownership or raw data boundaries.

Architecture

The system separates client-agent streaming from backend tool access. ACP handles the conversational transport, while MCP exposes read-only backend tools. AWS services handle media ingestion, classification, indexing and retrieval.

Agent Flow

The assistant can inspect user-owned posts, return inline media context, perform semantic media retrieval and produce scheduled activity summaries. User identity is controlled server-side, and vector retrieval is scoped to the current user.

Async Media Pipeline

The media flow runs asynchronously: S3 upload, EventBridge, SQS, classification Lambda, Bedrock vision model, classification state, indexing queue, Titan embeddings and S3 Vectors. Upload requests do not wait for expensive model work.

Security & User Isolation

The agent does not supply user identity to backend tools. Ownership checks and user-scoped retrieval are handled in the backend boundary, which keeps model output separate from authorization decisions.

Reliability & Idempotency

The implementation includes deterministic classification job handling and completed-job republishing for retry safety. This matters because event-driven pipelines can receive duplicate or repeated work.

Testing

The repository reports 229 passing automated tests: 145 backend tests, 67 ACP tests and 17 MCP tests. That is the strongest public evidence for the system’s engineering depth.

What I Built

My work focused on the agent boundary, MCP tool layer, asynchronous media processing, vector retrieval, retry/idempotency behaviour and ownership boundaries. The MCP service was containerised for ECS/Fargate deployment.

What I Learned

A large part of building an AI application is backend engineering. Identity, idempotency, retries, data ownership, observability and failure handling matter as much as the model call.
